**关键路径**：M0 → M1 → M2 → M3 → M4a → M4b → M5 → M6。  
**总计**：约 10–14 个工作日（不含 M7）。  
**可并行**：文案/阵营说明、音效、测试脚本、平衡模拟可以在对应里程碑内穿插，但不要抢在核心循环之前。

**8 分钟对预估的影响**：

- 单局 5 → 8 分钟（+60%）；1s 下落 + 1s 习惯思考（1s 后可再投，不强制等待）= 2s/颗期望，每局 150 → 240 球（+60%）。
- 技能 25 → 40 次（+60%）；150s/大招 2 → 3 次，达到“至少 3 次”目标。
- 手工验收 5 局：25 → 40 分钟（+15 分钟）；3 局：15 → 24 分钟（+9 分钟）。
- 平衡模拟 150 局（30 局 × 5 阵营）：游戏内时长 12.5 → 20 小时（+60%）；M6 预算 +0.5 天。
- 因此 M5 +0.25 天、M6 +0.5 天；总预估从 9–13 天上调到 10–14 天。

## M2. 3 阶 × 5 阵营数据化 + 换皮（1.5–2 天）

### 目标

把“5 种水果”换成“3 阶 × 5 阵营”的 15 种球；保留物理与合成骨架。

### 任务

1. `config.js` 定义：
   - `TIERS`：A 星 / B 月 / C 日，半径、清除分、合成分。
   - `FACTIONS`：金木水火土，颜色、纹样、技能/大招配置。
   - `SPAWN_POOL`：5 阵营 × {A,B}，权重可调。
   - `SCORE` 表、`MULTIPLIERS`、`SEQUENCES`。
2. `physics.js`：球体 `plugin` 改为 `{ faction, tier }`；`createBall(faction,tier,x,y)`。
3. `merge.js`：同阵营 + 同阶三消；3 个 C 清除（60 分）；跨阵营不合成。
4. `render/balls.js`：阶图形（星/月/日）+ 阵营色/环；不再画水果。
5. `index.html` / `styles.css`：标题、规则卡、进化路线、文案改为日月五行；保留深绿底风格。
6. `scoring.js`：替换为 3.3 计分表；删除 8 倍 combo；加本命阵营 ×2。
7. 测试：新增 `verify-merge-faction.js`，覆盖同阵营/跨阵营/3C。

### 验收

- 15 种球在画面上可区分（尺寸 + 图形 + 颜色三重编码）。
- 3 个同阵营 A → B；3 个 B → C；3 个 C → 清除（60 分）。
- 3 个不同阵营 A → 不合成。
- 计分表与 `AGENTS.md` 3.3 一致。
- 用户文字确认“能看出阵营和阶”。

### 风险

- 15 种球 × 3 消，难度可能过高；M6 用模拟调权重，必要时加“万能球”或“阵营转换”。

## M3. 8 分钟核心循环（1.5–2 天）

### 目标

一局能完整开始、进行、结束、重开；有计时、警戒线、序列、技能充能、结算。

### 任务

1. `state.js`：`phase = menu | playing | targeting | paused | over`；`timeLeft`、`feverUntil`、`skillCharge`、`ultCharge`。
2. `ui/overlays.js`：开始菜单（5 阵营选择）、暂停、结算、3 步教学占位。
3. `ui/hud.js`：倒计时、技能充能、大招按钮、本命阵营徽章、危险提示。
4. `main.js`：480s 基础倒计时（水大招最多 540s）；切后台/失焦暂停；时间到/溢出 `endRun(reason)`。
   - 放球节奏：`BALL_FALL_MS = 1000`、`DROP_COOLDOWN_MS = 1000`、`EXPECTED_THINK_MS = 1000`、`EXPECTED_DROP_CYCLE_MS = 2000`；1s 后即可再投，思考不强制。
5. `physics.js`：警戒线判定改为“持续 1.5s”；保留 2.2s 参数可配。
6. `sequences.js`：轴对齐序列检测（纯函数）+ 连线视觉 + 金色闪光。
7. `scoring.js`：`award(event)` 统一入口；本命 ×2、fever ×2；禁止直接改分。
8. 测试：`verify-timer.js`、`verify-sequences.js`、`verify-scoring.js`。

### 验收

- 从菜单选阵营 → 开局 → 480s 基础倒计时（水最多 540s）→ 时间到/溢出 → 结算 → 再来一局。
- 垂直 CCBBAA 与水平 ABCBA 可触发；斜线/错位/跨阵营不触发。
- 序列球只计一次分；大招充能 +1，上限 1。
- 暂停/切后台时，物理与倒计时都停。
- 重开清空所有状态。

### 风险

- 1s 下落 + 1s 习惯思考如果实测太慢/太快，改配置即可；1s 后即可再投，不强制等待；不要在逻辑里写死。
- 序列检测与合成检测的优先级要按 `AGENTS.md` 6.4 执行；否则第三个同阶球会先被合成掉。

## M4a. 火/水/木 三个阵营（1.5–2 天）

### 目标

先做三个“不需要复杂地形”的阵营，验证技能/大招节奏。

### 任务

1. `factions.js`：策略表 + 三个实现。
   - 火：技能 AAB 炸 B 周围；大招 BBCCAA 清火系 + 相邻一圈。

   - 木：技能 AABB 清一组；大招 3 次技能充能 → 30s fever ×2。

4. 测试：`verify-factions-fire.js`、`verify-factions-water.js`、`verify-factions-wood.js`。

### 验收

- 三个阵营都能在脚本场景中触发技能与大招。
- 水大招不突破 540s；木 fever 与本命叠乘最高 ×4。
- 火大招只炸一层，不递归；清球分数正确。

## M4b. 金/土 两个阵营 + 瞄准/地形（1.5–2 天）

### 目标

补齐最复杂的两个阵营，验证“选目标”和“改地形”是否好玩。

### 任务

1. 金：
   - 技能：手动选一个 B（需有 2 个相邻同阵营 A），消耗 B+2A，小范围爆炸；不暂停倒计时（暂定）。
   - 大招：CCBBAA 充能；进入 `targeting`，选一个含球阵营，把该阵营所有球转成金（保留阶）；跑最多 3 波合成/序列检测。
2. 土：
   - 技能：AABB 手动选择左/右 1/3 挡板槽位，加入/撤去；不暂停倒计时（暂定）。
   - 大招：AABBC 充能；进入 `targeting`，选左/右低端，把地面改成 33%–100% 斜坡，本局永久。
3. `ui/overlays.js`：瞄准态提示、取消按钮、8s 自动取消。
4. 测试：`verify-factions-metal.js`、`verify-factions-earth.js`、`verify-targeting.js`。

### 验收

- 金转换后能触发合成/序列，且不重复计分。
- 土斜坡不把球挤出边界；挡板最多 2 块；重开恢复水平地面。
- 瞄准时倒计时暂停；取消不消耗充能。

### 风险

- 土的地形物理最容易出 bug；先用简单旋转矩形，不要上复杂多边形。
- 金的全场转换可能引发级联；先限制 3 波，观察性能与分数。

## M5. 教学、反馈、移动端、分享（1.75–2.25 天）

### 目标

让新玩家 30 秒上手；让 demo 在手机上可玩、可分享。

### 任务

1. 3 步教学 overlay：三消 → 序列 → 大招；可跳过；首局自动出现。木阵营没有长序列，教学第 2 步改为“3 次技能充能大招”。

7. 测试：`verify-input.js`、`verify-mobile-layout.js`（DOM 断言，不截图）。

### 验收

- 用户文字确认：新玩家能看懂、手机不溢出、按钮可点。
- 结算页可重开、可分享文本。

## M6. 平衡模拟与最终验收（2–2.5 天）

### 目标

用数据确认 5 阵营没有明显强弱差、480s 基础节奏成立、性能达标。

### 任务

1. 写无头 bot（`work/sim-balance.js`）：固定种子，每阵营跑 30 局；480s 基础（水阵营最多 540s）× 150 局 = 20 小时以上游戏内时长，记录分数、合成数、技能数、大招数、溢出时间、最大球数。
2. 输出分布表：均值/中位数/P90、大招触发次数、溢出率。
3. 调 `config.js`：生成权重、技能间隔、大招序列长度、警戒线宽限、放球间隔。
4. 回归：`node work/check-all.js` + 手工 8 分钟一局。
5. 更新 `docs/OPEN_QUESTIONS.md` 的“已确认/平衡记录”。

### 验收

- 5 个阵营都能稳定打到 8 分钟附近，没有“必输”或“无脑赢”。
- 每局大招次数接近目标（按 150s 基准约 3 次；4 次不是目标）。
- 最大同屏球数 ≤ 160，帧循环不崩溃。
- `check-all.js` 全绿。

### 风险

- 如果 1s 下落 + 1s 习惯思考导致节奏太慢，优先调下落/冷却参数，不要改合成规则；1s 连投基础档 480 球（水延长档 540），技能 40 → 80 次（水档 90）作为模拟风险观察。
- 如果同阵营 3 消太难，优先调生成权重，不要直接降成“同阶即可”。
